# src/platform

Mobile-only adapters: device locale (`expo-localization`), MMKV storage, secure session and document storage (`expo-secure-store`), the network state (`expo-network`), the web crypto binding (`expo-crypto`), the app version and Sentry.
They implement interfaces defined in `src/core` and import nothing else from the app (`platform → core`, interfaces only).
MMKV, secure-store and expo-crypto are native modules: the app runs in a development build, not in Expo Go (see the README).

- `locale.ts`: `useDeviceLanguageTags`, the `LocaleAdapter` of `src/core/i18n` built on `useLocales()`; it re-renders when the OS languages change.
- `web-crypto-polyfill.ts`: side-effect import, first in `app/_layout.tsx` (before `intl-polyfills.ts`). Installs the binding of `web-crypto.ts` on `globalThis`, so `crypto.getRandomValues` and `crypto.subtle.digest` exist before the Supabase client draws a PKCE verifier (auth-js then sends an `s256` challenge, never a `plain` one from `Math.random`) and before the app storage key is drawn; a no-op where the engine has them.
- `web-crypto.ts`: `installWebCrypto(target)`, a Web Crypto binding on `expo-crypto` (the only importer of that package, enforced by the layer rules), for engines without one such as Hermes. It installs only the members the target lacks, each checked by kind (an object for `crypto` and `subtle`, a function for `getRandomValues` and `digest`), so an engine's own implementation is never replaced; once per target (a second call adds nothing), and a fresh module instance finds its members present. `getRandomValues` fills an integer typed array in place and returns it, refusing anything but an `ArrayBufferView` (`TypeError`), a float array or a `DataView` (`TypeMismatchError`) and more than 65536 bytes (`QuotaExceededError`), as Web Crypto does; `subtle.digest` supports SHA-256 only (a string or `{ name }`, ASCII case-insensitive), rejects other algorithms (`NotSupportedError`) and data other than an `ArrayBuffer` or an `ArrayBufferView` (`TypeError`), and resolves an `ArrayBuffer`. React Native has no `DOMException`: the errors are `Error`s with those names and fixed messages. Nothing else of `crypto.subtle` exists (auth-js's `getClaims`, which the app never calls, would need `importKey` and `verify`). `secureRandomValues` is the same `getRandomValues`, the `GetRandomValues` source of the app storage key.
- `intl-polyfills.ts`: side-effect import, second in `app/_layout.tsx`. Installs `Intl.PluralRules` (`@formatjs/intl-pluralrules`, English and French data) on engines that lack it, such as Hermes; a no-op where the engine has it.
- `storage.ts`: `createStorage()`, the `StorageAdapter` over one unencrypted MMKV instance (`tsuzuki`). It never holds secrets: preferences and the persisted query cache.
- `app-storage.ts`: `openAppStorage({ reporter, getRandomValues })` returns an `AppStorage`, `{ storage, persistent, firstLaunch }`: `storage` is the `StorageAdapter` over one MMKV instance encrypted with AES-256 (`tsuzuki-encrypted`), meant to replace `createStorage()`; `persistent` is false exactly when the process runs on `memory-storage.ts` (what it writes, a purge included, is gone when it ends); `firstLaunch` is true when neither the encrypted nor the unencrypted instance existed as the call started (a new install or a reinstall). **Not wired yet**: the composition root keeps `createStorage()` until a later change wires it with `secureRandomValues` (`web-crypto.ts`) as its cryptographically secure random source (`getRandomValues`, the Web Crypto signature). Its key (32 characters of the URL-safe base64 alphabet, one per random byte, 192 bits) is read synchronously from `expo-secure-store` (`tsuzuki-app-storage-key`, `WHEN_UNLOCKED_THIS_DEVICE_ONLY`) and kept in memory for the process (`app-storage-key.ts`). A first launch never reads it: the iOS keychain outlives an uninstall, so a key found without a file is stale, and a new key is written over it before the instance is created (nothing reported). No key or an invalid one while the encrypted instance exists is a lost key: the instance is deleted, reported (`key-lost`, `key-invalid`), and a new key is stored before a new instance is created. A key that does not open the instance (the check value under `app-storage.check` does not read back) clears it (`key-mismatch`); `app-storage-instance.ts`. A secure store that cannot be read or written, or an instance that cannot be opened, leaves the process on memory with every file untouched (`key-unavailable`, `open-failed`); so does MMKV that cannot tell whether the files exist (`open-failed`, `firstLaunch` false: a guess never replaces the key of existing files nor discards a session). The unencrypted instance `tsuzuki` is copied once (`app-storage-migration.ts`), in a crash-safe order: the copy, then its copied marker `app-storage.copied`, then the encrypted instance becomes the storage, then its marker `app-storage.migrated`; no process runs on the encrypted instance while the unencrypted one is unmarked. A failed copy or copied marker keeps the unencrypted instance as the storage of that process (`migration-failed`, copied again at the next launch); a failed encrypted marker keeps the encrypted instance (the next launch writes only the marker). The next launch deletes the unencrypted instance without opening it; a failed deletion is retried at the next launch (`legacy-delete-failed`). Without an unencrypted instance the missing marker is written, so a stray one appearing later is deleted unopened: nothing but the migration may open the unencrypted instance once the composition root is wired. Reports are `AppStorageError`s only, never the caught error or a key. Backups are not excluded: the encrypted files are useless without the key, which never leaves the device.
- `secure-documents.ts`: `createSecureDocumentStorage()`, a synchronous `StorageAdapter` over `expo-secure-store` (`getItem`, `setItem`, `WHEN_UNLOCKED_THIS_DEVICE_ONLY`) for the few small documents that must last while the app storage runs on memory: each device purge then records its user there (the core `createLocalDevicePurgeMarkerRepository` over this adapter), and the next launch on the files carries them into the purge markers. Keys are lowercase words joined by `.` or `-` (`TypeError` otherwise, the key not quoted), stored under `tsuzuki.documents.<key>`, a name no other item takes. A value over 2048 UTF-8 bytes throws a `RangeError` holding no value, before any write. expo-secure-store 57 deletes only asynchronously, and such a deletion could land after a later synchronous write: `delete` writes an empty tombstone instead, and an empty value reads as `undefined`. Calls throw what the secure store throws (a locked device); stored content is untrusted (its reader parses it with Zod); the items outlive an iOS uninstall.
- `secure-session.ts`: `createSecureSessionStorage(reporter)`, the `SessionStorage` for the auth session over `expo-secure-store`, readable only while the device is unlocked and never restored from a backup on another device (`WHEN_UNLOCKED_THIS_DEVICE_ONLY`). Values over 2048 UTF-8 bytes are unreliable there, so each value is split by code point into chunks under `<key>.<generation>.<index>`, in the generation (0 or 1) the stored header does not point to, then the header `<generation>:<count>` is written under `<key>`, last: a read returns the whole old or the whole new value, never a mix. The chunks no header points to are deleted afterwards; a failed deletion is reported to `reporter`, not thrown, and retried by the next write or removal. A write or a removal sets the cleanup marker `<key>.pending` before it touches a chunk or the header, and deletes it once its cleanup succeeded: a marker found on a key's first access in a process (the app was killed, or a cleanup failed) makes that access sweep first, inside the key's queue, every chunk key the header does not point to, so no stray chunk outlives the next launch. That costs one marker read per key per launch and two calls per write or removal, instead of a sweep of up to 96 keys at every launch. A read returns `null` (fail closed) when the header is missing or invalid (including the F-09 bare count) or a chunk is missing. Keys must match `^[\w-]+$`: the dot is reserved for the chunk suffixes. Calls are queued per key (a read never interleaves with an overwrite); a failed call rejects for its caller and does not block the next one. `createSecureSessionStorage(reporter, { discardStored: true })`, for a first launch (`firstLaunch` of `openAppStorage`): the first access of each key in the process first removes, inside its queue, whatever the key holds (the header first, then the chunks of both generations and the F-09 keys, then the marker), so no session, PKCE verifier or flow index stored before a reinstall is read; a key holding nothing costs a marker and a header read. A failed discard is reported with a fixed error (no cause, no value) and that access fails closed (a read gives `null`, a write or a removal rejects, changing nothing); the next access tries again, sweeping every chunk key. A key the process never accesses is not discarded. The stored layout (chunk keys, header, the F-09 keys) is in `secure-session-chunks.ts`, the cleanup marker and the sweep of a key's first access in `secure-session-sweep.ts`.
- `app-state.ts`: `subscribeToForeground(listener)`, over React Native `AppState`: calls the listener at once with whether the app is in the foreground (`active`), then on each change between foreground and not; returns the unsubscribe function. The composition root binds the auth token auto refresh to it, and passes it to `SessionLibraryContextProvider` as the core `ForegroundSubscription`: going to the background flushes the coalesced library writes, a return to the foreground replays the account library's queued writes.
- `connectivity.ts`: `createConnectivitySubscription(reporter)`, the core `ConnectivitySubscription` (`src/core/query/online-manager.ts`) over `expo-network`, the only importer of that module (ADR-0017). Each subscription listens to `addNetworkStateListener` and reads `getNetworkStateAsync()` once; online means `isConnected === true && isInternetReachable !== false` (reachability not known yet counts as online). An initial state read after an event is dropped, the event being newer; a failed initial read leaves the state to the events (the `onlineManager` keeps its last value, online by default) and is reported with the source `connectivity`. The composition root calls `followConnectivity(createConnectivitySubscription(reporter))`.
- `app-version.ts`: `APP_VERSION`, the version from `app.config.ts` (via `expo-constants`), used in the persisted cache buster with the core `CACHE_SCHEMA_VERSION`.
- `app-env.ts`: `readAppEnv(parse)`, reads `extra.env` (written by `app.config.ts`) through `expo-constants` and re-parses it with the core parser passed by the composition root (platform imports core types only); a missing or invalid env throws (fail closed).
- `sentry.ts`: `initSentry(env)` (errors only, on in release builds with a DSN, environment = app variant) and `createErrorReporter`, the core `ErrorReporter` (Sentry, or the console in development). The only production file allowed to use `console`.
- `sentry-scrub.ts`: the pure `beforeSend` / `beforeBreadcrumb` scrubbers (`scrubEvent`, `scrubBreadcrumb`): emails, JWTs, bearer tokens, Supabase keys and query string secrets replaced; auth, cookie and API key fields, request bodies, cookies and query strings, the user and notes dropped. Inside a text, the value of every key holding `note` is redacted wherever it sits, whatever precedes it (a long key prefix, an earlier value with a missing quote): a quoted value up to its closing quote (one followed by a space, `,`, `;`, `}`, `]`, `)`, `&` or the end), or to the end of the text when it has none; an unquoted value to the end of its line, or to the next `&` after `=`. The credentials scan does the same for every key holding `token`, `password`, `passwd`, `secret` or `apikey` (compared lowercased, without `-` and `_`), whatever its prefix and after an earlier value with a missing quote: a quoted value up to its closing quote (to the end of the text without one), a value opened by an escaped quote (JSON inside a JSON string) to the end of its line, an unquoted one up to a space, `&`, `#`, `,`, `;`, a quote, a bracket or a brace; a value starting with a bracket or a brace (already filtered, an array, an object) is kept. Both scans read each character a bounded number of times (`sentry-scrub-keys.ts`).
