# src/ui/components

Design-system primitives, the only place allowed to use NativeWind: layout (`Box`, `Stack`, `Row`, `Spacer`, `Screen`), content (`Text`, `Card`, `Chip`, `CoverImage` over `expo-image`, `Fact`), lists (`List` over FlashList, `MediaListItem`), controls (`Button`, `IconButton`, `Input`, single-line or a multiline text area, with an optional autofill kind (`autoComplete`: email, password or new password, also given to iOS as `textContentType`), `RadioGroup`, `Switch` over the react native `Switch`, `Pagination`), overlays (`Sheet` over the react native `Modal`, its panel above a `scrim` backdrop and lifted above the keyboard, with `SheetActions` for its Cancel and confirm footer) and states (`Spinner`, `EmptyState`, `ErrorState` for a whole screen, `InlineError` inside content, `Notice` for a lasting state the user can act on, its message one alert above its actions).
Announcements go through `useAnnouncement` (`announcements.ts`), also used by `ErrorState`, `InlineError`, `Notice` and `Input` (its error on iOS), with `announcementOf(title, message?)` joining a title and a message: views showing the same state pass the same key (`announceKey`), so it is announced once. Features never call `AccessibilityInfo` themselves.
State convention: a two-state control has a fixed label and states its state through the accessibility state (`checked` for radios and switches, `selected` for toggles such as the favorite heart); a control with more states names its state in its label and sets no state (`Chip`'s `stateInLabel`).
Props take theme token names only, never raw numbers or colors. Components never call i18n: every label (visible text and accessibility labels) comes as a prop from the feature.
